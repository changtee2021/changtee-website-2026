| ไฟล์ | บทบาท | ใครใช้ |
|---|---|---|
| [`content-writer-persona.md`](content-writer-persona.md) | **ตี๋** — นักเขียน | รอบเขียน |
| [`content-qc-persona.md`](content-qc-persona.md) | **เฮง** — บรรณาธิการตรวจ | รอบตรวจ |
| [`content-visual-persona.md`](content-visual-persona.md) | **อาร์ต** — ช่างภาพ/กราฟฟิก | รอบทำภาพ |

## ภาพรวมกระบวนการ

```text
บรีฟ → [ตี๋] ค้นข้อมูล+เช็คเทรนด์ → เสนอโครง → เขียน
     → [เฮง] ตรวจเนื้อหา → ผ่าน / แก้ให้ / ตีกลับ
     → [อาร์ต] ทำภาพ → QC ภาพ → เจอจุดผิดเจนใหม่
     → คนยืนยันจุด [ต้องยืนยัน] → ลง CMS
```

**กติกาสำคัญ:** ทั้ง 3 persona ต้องอยู่คนละ chat/session เสมอ  
ถ้าให้ AI ตัวเดียวเขียนแล้วตรวจต่อในบทสนทนาเดียวกัน มันจะ "เข้าข้างตัวเอง" และหาข้อผิดพลาดตัวเองไม่เจอ

**ทำไมอาร์ตถึงมาทีหลังเฮง:** ภาพต้องสื่อสิ่งเดียวกับเนื้อหาที่ผ่านการตรวจแล้ว  
ถ้าทำภาพก่อนแล้วเนื้อหาถูกแก้ทีหลัง ภาพจะขัดกับบทความทันที

## ขั้นที่ 0 — เตรียมบรีฟ (คนทำ 2 นาที)

กรอกให้ครบก่อนสั่งงาน ยิ่งครบ ยิ่งได้บทความตรงใจ:

```text
หัวข้อ:
คีย์เวิร์ดหลัก:
คีย์เวิร์ดรอง (ถ้ามี):
กลุ่มเป้าหมาย:        (บ้านใหม่ / รีโนเวท / คอนโด / โครงการ B2B)
หมวด (category):      choose / care / fabric / ideas / trend / motor / promo
ความยาวโดยประมาณ:
เป้าหมายบทความ:       (ให้ความรู้ / ช่วยตัดสินใจซื้อ / แก้ความเข้าใจผิด / ประกาศ)
ข้อมูลที่มีให้ใช้:      (ลิงก์ไฟล์ / ราคา / เคสจริง / รูป)
ห้ามพูดถึง:           (ถ้ามี)
```

ถ้าไม่รู้จะเติมอะไร ปล่อยว่างได้ครับ ตี๋จะถามกลับเอง

## ขั้นที่ 1 — สั่งตี๋เขียน

**เปิด chat ใหม่** แล้ววางคำสั่งนี้:

```text
อ่านและสวมบทบาทตาม docs/brand/content-writer-persona.md ทั้งไฟล์
แล้วเขียนบทความตามบรีฟนี้

[วางบรีฟจากขั้นที่ 0]

ข้อกำหนด:
- ค้นข้อมูลจริงในโปรเจกต์ก่อนเขียนเสมอ (src/lib/cms/, docs/)
- รันขั้นตอน Trend Radar ตามข้อ 6 ของ persona ก่อนวางโครง
- ข้อมูลที่ยืนยันไม่ได้ ให้ใส่ [ต้องยืนยัน: ...] ห้ามเดา
- เสนอโครง (title + H2 ทั้งหมด) ให้ดูก่อน แล้วรอผมอนุมัติค่อยเขียนเต็ม
- ส่ง field ครบตาม CMS ตามข้อ 9
```

**จุดที่ต้องหยุดดู:** ตอนตี๋เสนอโครงมา ให้อ่าน H2 ทั้งหมดก่อน  
ถ้าโครงเบี้ยว แก้ตอนนี้ใช้เวลา 1 นาที ถ้าปล่อยผ่านไปแล้วมาแก้ทีหลัง เสียเวลาทั้งบท

## ขั้นที่ 2 — สั่งเฮงตรวจ

**เปิด chat ใหม่อีกอัน** (สำคัญมาก — ห้ามต่อจาก chat ของตี๋):

```text
อ่านและสวมบทบาทตาม docs/brand/content-qc-persona.md ทั้งไฟล์
และใช้ docs/brand/content-writer-persona.md เป็นเกณฑ์อ้างอิง
ตรวจบทความนี้

[วางบทความเต็มจากตี๋ พร้อม field ทั้งหมด]

ข้อกำหนด:
- ตรวจข้อเท็จจริงจากไฟล์จริงในโปรเจกต์ ห้ามตรวจจากความจำ
- เคารพ Voice Lock ข้อ 2 อย่างเคร่งครัด
- รัน Voice Preservation Test ข้อ 5 แล้วรายงานตัวเลขให้ดู
- ส่งรายงาน 4 ส่วนตามข้อ 6
```

## ขั้นที่ 3 — อ่านผลตรวจ แล้วตัดสินใจ

| ผลตรวจ | ทำอะไรต่อ |
|---|---|
| **ผ่าน** | ไปขั้นที่ 4 |
| **ผ่านแบบมีแก้ไข** | อ่านตารางแก้ไข ถ้าเห็นด้วย → ขั้นที่ 4 |
| **ส่งกลับแก้** | กลับไป chat ของตี๋ แล้วสั่งตามด้านล่าง |

**คำสั่งเมื่อต้องส่งกลับให้ตี๋แก้:**

```text
บก.ตรวจแล้วมีจุดต้องแก้ตามนี้ครับ

[วางเฉพาะตารางรายการแก้ไข]

แก้เฉพาะจุดที่ระบุเท่านั้น ห้ามเขียนใหม่ทั้งบท
ห้ามแตะย่อหน้าที่ไม่ได้อยู่ในรายการ
```

**วนได้ไม่เกิน 2 รอบ** ถ้ารอบ 3 ยังไม่ผ่าน แปลว่าบรีฟมีปัญหา ไม่ใช่บทความ — กลับไปแก้บรีฟ

## ขั้นที่ 4 — สั่งอาร์ตทำภาพ 📷

**เปิด chat ใหม่อีกอัน** แล้ววางคำสั่งนี้:

```text
อ่านและสวมบทบาทตาม docs/brand/content-visual-persona.md ทั้งไฟล์
ทำภาพประกอบให้บทความนี้

[วางบทความฉบับที่ผ่าน QC แล้ว]

ข้อกำหนด:
- ลิสต์ก่อนว่าต้องการภาพกี่ใบ ใบไหนสื่ออะไร และเป็นประเภท A/B/C (ข้อ 2)
- **ภาพปก (cover) ต้องเป็นประเภท B เสมอ** — ห้ามใช้กราฟฟิกเป็นปก
- **ในเนื้อหาต้องมีภาพเหมือนจริงด้วย** อย่างน้อย 1–2 ใบ — ห้ามมีแต่กราฟฟิกทั้งบท (ข้อ 2 ของอาร์ต)
- ภาพเชิงเทคนิคหรือเปรียบเทียบในเนื้อหา ให้ใช้กราฟฟิกตาม Style Lock ข้อ 3
- ภาพเหมือนจริง ให้เขียน prompt ครบ 8 ช่องตามข้อ 5.1 + negative prompt ข้อ 5.5
- หาเรฟจากอินเทอร์เน็ตได้ แต่ต้องทำตามกติกาลิขสิทธิ์ข้อ 6.1 และแนบลิงก์เรฟมาด้วย
- ห้ามให้ AI เจนตัวอักษรไทยลงในภาพ (ข้อ 3.1)
- QC ทุกใบตามข้อ 9 เจอ Critical ให้เจนใหม่ทันที ตามนโยบายข้อ 9.4
- ส่ง alt text + caption + รายงาน IMAGE-QC มาด้วย
```

**จุดที่ต้องหยุดดู:** ตอนอาร์ตลิสต์ภาพมา ให้เช็คว่าเลือกประเภทถูกไหม  
เนื้อหาที่ต้อง "เปรียบเทียบ" หรือ "ชี้จุด" ต้องเป็นกราฟฟิกเสมอ อย่าปล่อยให้ทำเป็นภาพเหมือนจริง

**ถ้าภาพยังดูเป็น AI** สั่งซ้ำแบบนี้:

```text
ภาพใบนี้ยังดูเป็น AI เจนอยู่ ให้ไล่ตามข้อ 4 (อาการ) ว่าติดข้อไหนบ้าง
แล้วแก้ prompt ตามข้อ 5 ก่อนเจนใหม่
เน้นเพิ่ม: ทิศทางแสงเดียวชัดเจน, ระยะชัดตื้น, ความไม่เรียบร้อย 2 อย่าง,
บริบทไทย 2 อย่าง, ลุคฟิล์ม
และตัดคำต้องห้ามข้อ 5.4 ออกให้หมด
```

**เพดานการเจน:** 3 รอบต่อ 1 ใบ ถ้ายังไม่ผ่านให้เปลี่ยนเป็นกราฟฟิกแทน — อย่าเจนวนไม่จบ

## ขั้นที่ 5 — คนยืนยัน (ห้ามข้าม) ⚠️

เปิดดูรายการ `[ต้องยืนยัน: ...]` ทั้งหมด แล้วเติมข้อมูลจริงด้วยมือ

รายการที่ **ต้องมีคนเป็นคนตัดสินเสมอ**:

- ราคา ส่วนลด โปรโมชัน
- เงื่อนไขและระยะเวลารับประกัน
- ชื่อ/รูป/ที่ตั้งของลูกค้าจริง
- ขอบเขตพื้นที่บริการ ค่าเดินทาง
- คำเคลมเชิงสุขภาพหรือความปลอดภัย

**ตรวจภาพด้วยตาคนอีกรอบ** — เปิดภาพขนาดเต็มแล้วดู 3 อย่างนี้:

- มีตัวอักษรมั่วหลุดมาไหม
- ผ้าม่านแขวนกับรางถูกต้องไหม
- ภาพขัดกับสิ่งที่บทความเขียนไหม

**ถ้ายังมี `[ต้องยืนยัน]` ค้างอยู่แม้แต่จุดเดียว ห้ามกดเผยแพร่**

## ขั้นที่ 6 — ลง CMS

เข้า `/admin/cms/blog/new` แล้วกรอกตาม field ที่ได้มา:

| ช่องใน CMS | เอามาจาก |
|---|---|
| หัวข้อ | `title` |
| Slug | `slug` |
| คำโปรย | `excerpt` |
| เนื้อหา | `body` |
| หมวดหมู่ | `category` |
| แท็ก | `tags` (คั่นด้วย `,`) |
| ผู้เขียน | `ทีมช่างตี๋` |
| SEO Title / Description | `seoTitle` / `seoDescription` |
| ภาพปก | ไฟล์ `-cover.webp` ใน `public/images/blog/` ที่อาร์ตส่งมา |

**ก่อนกรอก** เอาไฟล์ภาพจากอาร์ตไปวางใน `public/images/blog/` (ทั้งปกและภาพในเนื้อหา) แล้วอ้าง path ในเนื้อหาแบบนี้:

```text
![alt ที่อาร์ตเขียนมา](/images/blog/ชื่อไฟล์.webp "caption ที่อาร์ตเขียนมา")
```

**บันทึกเป็นฉบับร่างก่อนเสมอ** → กดพรีวิว → อ่านบนมือถือ 1 รอบ → ค่อยเผยแพร่

**ที่เก็บภาพบทความ (ยึดแบบนี้):** ปกและภาพในเนื้อหาอยู่ที่ `public/images/blog/` ทั้งคู่  
ชื่อปกลงท้าย `-cover.webp` เช่น `dimout-vs-blackout-cover.webp`  
อ้างใน CMS field `cover` เป็น `/images/blog/...` ไม่แยกไป `generated/` แล้ว (โฟลเดอร์ `generated/` เก็บของเก่า/ภาพอื่นบนเว็บ)

## แผนเนื้อหา 50 บทความ (Content Roadmap) 🎯

เป้าหมาย: ให้บล็อก **ครอบคลุมหมวดสินค้าทั้ง 7 pillar + ทุกหมวดบล็อกหลัก** แบบมีลำดับ ไม่ปั๊มทั้งหมดวันเดียว

| เป้า | จำนวน | เหตุผล |
|---|---|---|
| ชุดเริ่มต้น (starter) | 18 รวม | ครบ 7 pillar + หมวดบล็อกหลัก แบบไม่ดูเหมือนปั๊ม |
| **เป้าหมายถัดไป** | **50 รวม** | ครอบคลุมทุกสไตล์สินค้าย่อย + ปัญหาที่คนค้นจริง + B2B + เทรนด์ |
| เกินจากนี้ | เฟส 3 | รอ Search Console / คำถามลูกค้าจริงก่อนขยายต่อ |

**กติกา:** หน้าสินค้า (~39 SKU) ทำหน้าที่ SEO รายละเอียดอยู่แล้ว  
บทความบล็อก = คู่มือช่วยตัดสินใจ ที่โยงเข้า `/products/...` และ `/quote` ไม่เขียนซ้ำสเปกทีละรุ่น

**ห้ามอัปทั้งชุดวันเดียว** — ปล่อยทีละ 4 บทต่อรอบ (ดูตารางปล่อยท้ายตาราง) `publishedAt` ต้องตรงวันที่ปล่อยจริง ห้าม backdate
